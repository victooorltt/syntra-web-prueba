2. DETALLE DE CAMBIOS EN base44/functions/notifyNewLead/entry.ts (Deno Hook)
------------------------------------------------------------------------
Se ha reemplazado la lógica de la función `notifyNewLead` con una solución robusta y tolerante a fallos para producción:
- **Lectura de Variables de Entorno**: Se leen dinámicamente mediante `Deno.env.get(...)` las variables `OPENAI_API_KEY`, `NOTION_API_KEY`, `NOTION_DATABASE_ID`, `RESEND_API_KEY`, y los correos de envío/recepción.
- **Manejo de Errores e Independencia**:
  - **Agente de IA (OpenAI)**: Analiza el mensaje, presupuesto y empresa para inferir de manera precisa el `sector`, `service` (mapeado a "Automatización", "Diseño web", "Agente IA", "Otro"), `goals`, `timeframe` y si contiene `website`. Si el API call falla o no está configurado, la función continúa utilizando valores por defecto coherentes.
  - **CRM Notion**: Realiza la inserción del lead y sus campos en Notion usando `@notionhq/client`. Si la llamada falla, registra el error y prosigue sin bloquear el flujo.
  - **Notificaciones Resend con Fallback**: Intenta enviar la alerta de lead formateada en HTML mediante la API de Resend. Si no hay clave de Resend o la llamada falla, se activa automáticamente el método de respaldo nativo de Base44 (`SendEmail` de Core Integrations) para garantizar la entrega del correo al equipo.

3. INTEGRACIÓN CON VERCEL SERVERLESS (api/notifyNewLead.js)
------------------------------------------------------------------------
Para facilitar las pruebas de integración y despliegue del formulario directamente en la infraestructura de Vercel:
- **Enrutamiento local**: Se creó `/api/notifyNewLead.js` que implementa la misma lógica asíncrona tolerante a fallos en Node.js (utilizando ES Modules ya que la app está configurada con `"type": "module"`).
- **Consumo directo**: El componente `ContactForm.jsx` ahora realiza un `fetch('/api/notifyNewLead')` con un método `POST` y formato JSON.
- **Robustez**: Cada API externa (OpenAI, Notion, Resend) está protegida por su propio bloque `try-catch`. Si una llamada falla, se registra en consola y la función continúa con las siguientes operaciones, retornando siempre `res.status(200).json({ ok: true })` para no romper la experiencia de usuario y facilitar la depuración a través de los logs en el dashboard de Vercel.

4. CONFIGURACIÓN DE VARIABLES DE ENTORNO EN VERCEL
------------------------------------------------------------------------
Para que la función de Vercel opere correctamente, es indispensable registrar las siguientes variables de entorno en el panel de tu proyecto en **vercel.com** (bajo `Settings > Environment Variables`):

1. **Variables Obligatorias / Recomendadas**:
   - `OPENAI_API_KEY`: API key de OpenAI (ej. `sk-proj-EVTH...`).
   - `NOTION_API_KEY`: Secret de integración interna de Notion (ej. `ntn_6159...`).
   - `NOTION_DATABASE_ID`: Identificador de base de datos del CRM en Notion.
   - `RESEND_API_KEY`: Clave API de Resend para notificaciones por correo (ej. `re_LTXJ...`).
   - `EMAIL_FROM` (o `RESEND_FROM_EMAIL`): Dirección remitente verificada en tu cuenta de Resend (ej. `info@ltevo.com` o el dominio propio verificado).
   - `EMAIL_TO` (o `RESEND_TO_EMAIL`): Dirección de correo destinataria donde recibirás los leads (ej. `info@syntralabs.es`).

2. **Desarrollo y Pruebas Locales**:
   - Ejecuta tu proyecto local usando `vercel dev` para emular el entorno de funciones serverless de Vercel en local. Este comando levantará la aplicación e interceptará las peticiones a `/api/notifyNewLead` redirigiéndolas automáticamente al archivo local `api/notifyNewLead.js`.
